    public: \
        static exportMacro ::bmalloc::api::IsoHeap<isoType>& bisoHeap(); \

        exportMacro void* operator new(size_t size);\
        exportMacro void operator delete(void* p);\
        ...
        exportMacro static void freeAfterDestruction(void*); \

Source/bmalloc/bmalloc/IsoHeapInlines.h:155-162
    static ::bmalloc::api::IsoHeap<isoType> heap("WebKit "#isoType);
    return heap;
    }
    void* isoType::operator new(size_t size)
    {
        RELEASE_BASSERT(size == sizeof(isoType));
        return bisoHeap().allocate();
    }

=> The binary signature of an ISO class is a mangled `_ZN6bmalloc3api7IsoHeap...`
   (plus `bisoHeap()`), and its `operator new` is *defined* in the class's own TU.
   With the gate off, no such symbol can exist and `operator new` is inlined into
   `::WTF::fastMalloc`, which is an undefined symbol in the same object.

## 4. What fastMalloc is on a USE(SYSTEM_MALLOC) build

Source/WTF/wtf/FastMalloc.cpp:156  #if USE(SYSTEM_MALLOC)
Source/WTF/wtf/FastMalloc.cpp:236  void* fastMalloc(size_t n) { ... void* result = malloc(n); ... }
Source/WTF/wtf/FastMalloc.cpp:265  void fastFree(void* p)  -> free(p)

=> the 834 classes land in libc malloc, i.e. ASAN's allocator, on the oracle.
   On the console (bmalloc, ISO off per the port default) they land in the general
   bmalloc heap - which is what docs/107 §3 already recorded.
